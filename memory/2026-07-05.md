# 2026-07-05 日志

## comparable_sales suburb 名称归一化

### 背景
comparable_sales 从 REA/Domain 抓取时有大小写混用（如 `Brighton` 和 `brighton`），导致 238 组区名被计为不同区，实际 unique suburb 从真实值被夸大为 764 个。

### 操作

1. **一次性 UPDATE**（12:05）：
   ```sql
   UPDATE comparable_sales SET suburb = LOWER(TRIM(suburb))
   WHERE suburb != LOWER(TRIM(suburb))
   ```
   受影响行：9,540 条
   unique suburb：764 → 526

2. **DB 触发器**（12:10）：
   - 函数：`normalize_comparable_suburb_func()` — `NEW.suburb := LOWER(TRIM(NEW.suburb))`
   - 触发器：`trg_normalize_suburb` — BEFORE INSERT OR UPDATE ON comparable_sales
   - 创建方式：pg.Client（@neondatabase/serverless 的 multi-statement 创建有问题）
   - 验证：三种路径均生效（pg.Client direct, sql\`\` tagged template, sql.unsafe）
   - 覆盖所有 INSERT/UPDATE 入口，无需逐个改 20+ 个脚本

### 影响
- 所有 valuation/opportunity/planning 代码中 `LOWER(cs.suburb)` 查询继续正常工作
- 硬编码 `WHERE suburb = 'Armadale'` 等查询需要改小写（少数脚本/临时分析用）
- 后续数据入库自动小写

### 结论
suburb 归一化完成。后续不会再产生大写/小写混用的区名。
